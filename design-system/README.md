# The Way I AI · Design system

The shared presentation layer for a collection of source-owned topics. Every page ships two designs, switched in place from the masthead and remembered in local storage.

**Field Atlas** (the default; `atlas.css`, `atlas.ts`) presents the collection as a naturalist's atlas: sage-grey paper, numbered topics, wildlife portraits mounted on warm card with double hairline frames, Cormorant Garamond display type, Spectral reading text, and IBM Plex Mono labels. Dark mode is a herbarium at night; portraits keep their paper and are never inverted. The home page sets the wordmark beside an unframed introduction, with a faint, slowly turning stamp ring showing through it and the masthead, a paged “Browse the topics” spread, and a category-filtered topic list. Topic pages have a mounted portrait with a label card, an outline of dots, a running head that tracks the current chapter, margin notes, framed panoramas, previous/next topic cards with portraits, an “All topics” drawer (on every page but the home page, which lists the topics itself) and, on phones, a bottom bar. `general-index/index.html` is the A–Z index of every authored chapter and subsection. Reader-facing words stay plain (Topic 4, No. 4, Category, A–Z index); see AGENTS.md. The masthead shares Folio's geometry so the design switch never moves. The wordmark keeps its Newsreader lettering and wave; only its ink colours change.

The **Folio** design pairs warm paper, dark ink, copper accents, Newsreader headings and prose, and DM Sans navigation. The homepage is an editorial collection with the selected **F · Murmuration** background at **20% intensity**, configured in `topics/topics.json` with `ambientBackground: "F"` and `ambientIntensity: 0.2`. On the site, topic pages have an optional collection sidebar and a section outline to the left of the article on desktop, becoming a disclosure above the article on narrow layouts. The outline precedes the article in DOM order too, so keyboard navigation matches the layout. The collection's display title pairs plum with teal through `--title-ink` and `--title-accent`, with lighter variants for dark mode. Font and code-renderer licenses are in `licenses/` and are embedded in the generated files.

## Homepage entrance

Rotating phrases written as `[first|second|third]` in the collection introduction slide up one after another in a secondary highlight colour (Folio ochre, Atlas teal, distinct from the heading accent), 3 seconds each, and pause while hovered or focused. The phrase window eases to each phrase's width, so the following punctuation moves with it. A phrase never wraps: one too long for the rest of its line shrinks its font to fit. If the longest phrase would need less than 60% of the normal size, all phrases move to a line of their own instead, so the layout stays stable and readable. Folio's introduction heading is sized so the introduction is never taller than the wordmark beside it. Without JavaScript, in print, or with motion reduced, the first phrase stays; screen readers get every phrase once.

The large home page wordmark has its own arrival: “the way” rises, the shared I drops in with a small bounce, the last line rises as it lands, then the wave fades in (`logo-*` keyframes in `theme.css`). It is split into inline parts at word boundaries only, so letter positions match the unsplit wordmark. `logo.ts` plays one rare trick after 20 seconds of inactivity, at most every one to two minutes, in shuffled order, never twice in a row:

- **Moves:** backflip, ripple, wave, swap and correct (“IA” with a spell-check squiggle), topple (“way I” flips over its baseline onto “AI” and is heaved back up), magnet (a horseshoe magnet pulls the A, dragging the other letters behind it).
- **Light and energy:** failing light (film-style flicker), alien glow, glitch broadcast (channel split, tears, and a “NO SIGNAL” frame that holds for over a second). Flicker and glitch stay under the WCAG 2.3.1 flash limit: no area changes brightness more than six times (three flashes) in any second. Keep step changes about 130ms or more apart when editing them.
- **Nature:** butterfly.
- **Showpieces:** time travel (the logo leans back like a car, shoots off along a banking curve leaving two converging fire trails, and drops back in like a helicopter) and origami (it folds into a paper plane that loops around, glides back level, and unfolds into the letters).

Secret triggers: triple-click the home page wordmark to play the next trick, or type “ai” outside a text field to open a small menu listing every trick by name (plus “Surprise me”). Choosing one plays exactly that trick, interrupting any trick in progress. No trick plays, automatically or on request, while motion is reduced; typing “ai” is a single-key shortcut and is off with the others. Every element a trick adds carries `.logo-temp` and is removed when it ends, and every letter returns to its resting position. Rotation temporarily turns the I into a box and compensates its letter-spacing, so nothing else moves. The full stop after rotating phrases notices each change a beat late, swells, and hurries after the new end.

The logo/slogan section enters first; the collection (and, in Field Atlas, the “Browse the topics” spread) follows after 500ms. Both use a one-time fade, a 90% → 100% zoom, and a downward arrival from above, inspired by the [Makerkit demo](https://next-supabase-saas-kit-turbo-demo-vercel-web.vercel.app/). Durations are 800ms and 1000ms respectively, with `ease` timing. Travel is shorter than the reference to fit Folio's compact layout, and shorter again on narrow screens. The masthead stays stationary; Murmuration continues independently at 20%.

The entrance is CSS-only, including offline/no-JavaScript pages. It reserves the final layout space, leaves no persistent transform, and does not replay on theme changes or resize. Reduced-motion and print show both sections immediately. Keyboard focus reveals the focused section immediately; with JavaScript, it finishes both entrances so focus cannot cause a replay. The standalone background gallery omits this page-load choreography.

## Responsibilities

- `theme.css`: Folio tokens, typography, layouts, responsive behavior, dark mode, and print styles, plus the shared design-visibility, design-switch, and A–Z index rules.
- `atlas.css`: Field Atlas tokens and components, scoped to `:root[data-design='atlas']`.
- `design.ts`: pre-paint application of the saved design (`the-way-i-ai-design`), defaulting to Field Atlas.
- `atlas.ts`: the design switch (a 200ms cross-fade that keeps the reading position), spread paging and the pointer-following tilt of the spread portrait, category filter, topic drawer, running head, plate turning, and the mobile plate bar, whose links show the neighbouring animals by reusing the previous/next cards' thumbnails.

Sidebars use the shared `--sidebar` shade (between paper and tint; the surface colour in Atlas dark) with hairline edges, on desktop only: in Folio the collection sidebar and the outline are two full-height panes that fade with focus mode; in Atlas the outline is a framed panel that bleeds into the margin so its text keeps the content edge. The Atlas margin notes stay on the page colour, like a book margin. Shared reader details (`reader.ts`, `theme.css`): the outline fades at whichever scrolling edge hides more of it; each topic ends with a tailpiece showing its own animal, cloned from the topic drawer's thumbnail so its bytes are shared; “?” (while shortcuts are enabled) or the footer’s “Settings” button opens preferences followed by a list of only the keys the current page understands. Touch screens show only preferences. The keyboard follows one model in both designs, grouped the same way in that list. **Move:** J/K focus the next or previous item: topics on the home page (the Atlas spread turns to the same topic), chapters on topic pages, letters on the A–Z index, sections on site pages; a press during a jump's smooth scroll counts from that jump. Home/End select the first or last topic. **Open:** Enter, because selection is real focus on a real link (⌘/Ctrl+Enter opens a new tab); the Atlas spread is a single Tab stop whose arrows select and whose Enter opens. **Go:** ⌘/Ctrl+K search, [ and ] previous or next topic, G then T all topics (drawer or collection sidebar), H home, I A–Z index, A About. **Change:** F focus mode, C copy a link to the current section, S share, T theme, D design, Esc backs out one level. None act while typing or with a dialog open. In focus mode, keys that need the hidden navigation (/, G then T, the outline skip link) leave focus mode first; the rest keep it, and F does nothing while the topic drawer is open. Topic pages have two skip links, to the text and to the outline; dates are not Tab stops. Header tooltips name each control's key. On phones the design switch becomes a single palette icon for the other design. The masthead’s share icon opens a dialog built from the page’s own Open Graph tags: the sharing card, the canonical link with “Copy link”, the device share sheet where `navigator.share` exists, and plain email, LinkedIn, Bluesky and X links that load nothing until followed. Phone-width topic pages have no room in the masthead, so their share button sits after the tailpiece. The card image resolves beside the page in a built bundle (`npm run build:site`) and falls back to the published copy when sharing cards have not been rasterized locally. Dates (`time[data-age]`) read as how long ago, to the month, computed in the browser so output never depends on the build date; the exact date slides in on hover, focus or tap, and is what screen readers and no-JavaScript readers get. The phone bottom bar with the neighbouring animals appears in both designs. The A–Z index is linked from every footer and from Folio’s collection sidebar. Atlas pages take their inset from the masthead’s `--header-inset` and fill the same 1600px shell, so the logo, content and GitHub icon share both edges at every width.

Both designs animate opening and closing: disclosures animate their height (`reader.ts`), the search dialog scales in and out, the topic drawer slides, focus mode moves navigation aside (the atlas centres its text column by animating `--atlas-toc`), and theme and design changes cross-fade with View Transitions. Reduced motion disables all of it: the device setting, or the reader's Animations switch, both resolved by the head script (`design.ts`) into `data-motion="reduce"` before first paint. Scripts check that attribute (not the media query) and listen for `motion-change`; `theme.css` mirrors the reduced-motion kill switch for it.
- `reader.ts`: collection/section search, navigation, code copying, theme controls, explorer selection, animated focus mode, and scroll-responsive header.
- `theme.ts`: pre-paint System resolution, temporary manual overrides, two-hour inactivity expiry, persistence, live system changes, and cross-tab updates.
- `murmuration.ts`: the shared particle renderer used by the homepage and preview study F, with identical geometry, timing, and palettes.
- `ambient.ts`: homepage-only canvas lifecycle; capped pixel density and 30 fps, a still frame for reduced motion, and suspension in background tabs, cached pages, and print.
- `search.ts`: creates the shared collection-wide index, loaded on demand from rendered prose and original code; result URLs remain relative.
- `layout.ts`: collection and reader layouts; receives all collection and topic copy from source metadata.
- `wordmark.ts`: validates the saved wave geometry and generates its scalable, static CSS projection.
- `explorers.ts`: a generic SVG-and-panels renderer. It resolves Markdown section/excerpt references and highlights named SVG nodes.

Topic-specific copy, diagram labels, SVG geometry, and explorer configuration belong in `topics/<id>/`, not here. Collection copy and topic order live in `topics/topics.json`; newlines in the opening statement create authored display lines, and the optional `introductionAccent` identifies the phrase rendered in the collection accent color. A new topic needs no changes to this directory unless it introduces a genuinely new reusable presentation component.

## Build contract

`scripts/build.ts` reads the registry, each topic's main README (YAML front matter plus Markdown), listed companion documents, and assets. `scripts/markdown-source.ts` validates metadata and document paths. There are no per-topic presentation modes, separate `topic.json` files, or heading offsets. It renders Markdown with Marked, pre-renders code examples with Pierre, and publishes shared fonts, styles, behavior and responsive artwork alongside small HTML pages in `_site/`. The single-file HTML edition is retired. Validated explorer diagrams remain inline so their nodes can be selected. The code examples use declarative shadow DOM with a JavaScript fallback for older browsers. All narrative text is available without JavaScript.

Optional AI illustration families are discovered through `topics/<id>/assets/illustrations/manifest.json`; see the [delivery guide](illustration-style/README.md) and [generation prompt](illustration-style/single-topic-illustration-prompt.md). Exact document/chapter bindings are validated before writing output. Missing artwork renders nothing; homepage slots remain empty. Version 3 species-only wildlife manifests supply one shared, uncropped 16:9 portrait and four decorative 4:1 panoramas. The renderer spaces these before chapter boundaries in reading order without chapter bindings or topical meaning; all have empty alt text. The first chapter of each document is left uninterrupted; missing files keep their assigned slots empty. See the delivery guide for the deterministic spacing algorithm and species-only ZIP format. Version 1/2 semantic artwork remains supported.

Version 2 illustration manifests supply one shared 16:9 main image (`hero.webp`) for both the homepage and article top, plus native 4:1 chapter images. Artwork retains its warm-paper background in both themes, is shared, responsive WebP, and is never inverted. The homepage shows the shared main image at 16:9; the article top reuses exactly the same source in a centered 4:1 crop. All chapter artwork displays at 4:1. Version 1 deliveries remain supported with centered crops and reuse of their homepage source rather than their retired separate article hero. Chapter strips sit after the corresponding `##` heading, without modifying prose or derived outlines.

Local Markdown images become shared files. Raster artwork gets content-addressed WebP variants at 320, 640, 960, 1280 and 1600 pixels, bounded by the original size. The browser chooses a variant with `srcset` and `sizes`; chapter strips and cards load lazily, and article portraits have high fetch priority. Navigation uses 360px WebP copies. Font files are Latin subsets and are fetched only when a design uses the corresponding face. Syntax-highlight styles are shared even across code-block shadow roots. SVG sources used inline must be standalone, script-free, and free of external render dependencies. Assets can use the shared CSS variables, with fallback values for opening the SVG on its own.

See the root README for [build and verification commands](../README.md#editing-and-adding-topics-notes-to-self) and [publication bundle usage](../README.md#publishing-to-github-pages-notes-to-self). `npm run check` rejects stale output, invalid source references, broken links, duplicate IDs, and external render dependencies. Browser acceptance coverage is defined in [`tests/reader.spec.ts`](../tests/reader.spec.ts).

The homepage masthead omits the home wordmark because the hero already presents it at full scale; its search and right-side controls align to the collection content edges. Topic mastheads place search directly after the home wordmark, with no redundant “The collection” link. Theme and GitHub controls remain at the right. On desktop topic pages, the logo and search shift left as the collection sidebar collapses; header padding and the sidebar grid share the same motion token. Mobile keeps a stable header inset while navigation disclosures stack above the article. The only repository navigation link is the GitHub icon at the masthead's far right. The adjacent icon-only theme button immediately switches to the opposite resolved theme; there is no popup. Its icon and accessible name describe the destination: a moon to switch to Dark, a sun to switch to Light. System is the default and follows live device changes. Controls have accessible names and native keyboard behavior. Avoid promotional taglines or extra sidebar/footer links.

On topic pages, the collection sidebar is a native disclosure, collapsed until the reader changes it and then restored from local storage on later navigations. Desktop grid columns animate its expansion/collapse; reduced-motion preferences disable transitions. On desktop, the open collection sidebar, section outline, and centered reading column have pointer- and keyboard-operable resize handles; the compact mobile layout retains fixed widths. The header’s icon-only focus control animates both navigation columns and the masthead away, then moves into the viewport corner so navigation can be restored; the sequence reverses when leaving focus mode. Escape also leaves focus mode. Theme choice, focus mode, collection disclosure state, all desktop column widths, and per-topic reading positions persist in local storage; unavailable storage falls back to in-memory defaults without blocking reading. There is no reading-progress indicator. Scrolling beyond 120px compacts the header; returning within 16px of the top restores it. The separate thresholds prevent layout-height changes from repeatedly retriggering the transition. Full text and native disclosures remain available without JavaScript.

A manual theme override expires after **two hours without scrolling, typing/keyboard input, or navigation**. One local-storage record (`the-way-i-ai-theme`) keeps the choice and last-activity timestamp together across pages and tabs. Activity writes are throttled to once per second and flushed on leaving; navigation and theme selection save immediately. Check expiry before recording a new navigation or interaction, so returning after a long absence cannot renew a stale override. Recheck on visibility/focus, device changes, and cached-page restores to handle sleeping devices and throttled timers. Pointer movement, ordinary button clicks, and tab focus alone do not renew it. Legacy untimed preferences default to System. Blocked storage retains selection and expiry in memory.

The shared `.wordmark` renders the same live lettering and decorative wave in the collection title and every topic page's home link. Set `--wordmark-size` to resize it; all spacing, optical letter adjustments, and background coordinates follow that size. Each topic home link has an accessible name and its decorative text is hidden from assistive technology.

The “On this page” search filters the outline by matching heading or section content and highlights every visible occurrence in both the outline and document. Collection-wide search highlights matches in its result list and carries the query into the destination page’s local search through the `q` URL parameter.

All topics share one editorial contract: the main Markdown title is the only page title and is reused on cards, in navigation, and in search. Front matter supplies one description. Authored `##` chapters and `###` subsections form a nested, clickable outline, preserving their wording and numbering. Single-document topics have no synthetic source label or repeated title. Multipart topics group the outline by actual document titles; companion documents have named section boundaries without repeating the main title. Every listed document's complete text is rendered.

The homepage reverses canonical collection order, putting newest-added topics first while retaining topic numbers, sidebar order, and next-topic navigation. Topic titles are plum, chapters teal, and subsections copper, with light/dark variants. Full-width chapter hairlines fade from solid left to transparent right; subsections use shorter fading marks. The first body heading has neither the normal large chapter gap nor a separator. Adjacent TOC entries without subsections are more closely spaced than groups with nested entries.

The topic title, description, and dates share an 800ms fade/90%-to-100%-zoom/downward entrance. Every chapter and subsection visible in the initial viewport follows together on a shared timeline with a 500ms delay after the header starts. Later chapters and subsections reveal independently as they enter the viewport, once per page visit, without affecting layout. Browser behavior progressively groups the authored heading blocks; static HTML remains complete. Direct links, keyboard focus, section search, browser find, restored positions, reduced motion, missing IntersectionObserver, and print bypass pending entrances as appropriate. No-JavaScript readers retain full content and nested navigation. See [AGENTS.md](../AGENTS.md#editorial-structure-and-shared-presentation) for authoring and maintenance rules.

Machine-readable discovery uses `siteUrl` and `author` in `topics/topics.json` plus the existing topic metadata. `scripts/discovery.ts` generates a canonical link, basic Open Graph metadata, and JSON-LD (`WebSite`, `CollectionPage`, or `Article`) without changing visible content. All canonical page URLs use clean trailing-slash folder addresses. Navigation keeps explicit relative `index.html` filenames. Navigation remains relative for offline reading. Canonical links are identifiers, not network-loaded rendering dependencies. See the [site icon guide](assets/favicon/README.md) for approved artwork and delivery; `npm run check` verifies icon copies in an existing bundle byte for byte.

Social previews use the approved static Atlas card layout in `sharing.css` and the shared `wordmarkContent` renderer. `scripts/sharing.ts` creates card documents from collection/topic metadata and existing portrait images, never separate prose copies. Publication builds (`npm run build:site`, also used by `npm run dev -- --site`) render one 1200×630 JPEG per topic plus the collection card with Playwright Chromium, embedded fonts, and no runtime network requests. The A–Z index reuses the collection card; topics without artwork get a text-only card. Long titles shrink to fit without truncation. Open Graph, Twitter Card, and JSON-LD image metadata use absolute HTTPS URLs with source-derived hashes for cache invalidation. JPEGs are generated only in `_site/assets/sharing/`; platform-dependent rasterization is not compared against checked-in images. Local `npm run build` builds and `--check` compute source-addressed metadata without launching a browser. Inspect the published JPEGs in `_site/assets/sharing/` after a publication build.

`sitemap.xml` is generated from the same published HTML inventory, excluding unpublished Markdown pages, previews, and source documents. Article `lastmod` uses `updated`, falling back to `created`; collection and index dates are omitted rather than guessed. `npm run check` detects a stale sitemap in an existing `_site/` bundle. The authored root `robots.txt` is copied into the publication bundle and references the sitemap. It allows search crawlers while excluding known training crawlers and usage-control tokens; these voluntary rules are not access controls. When changing `siteUrl`, update the sitemap reference in `robots.txt` too. The local preview serves XML and robots rules with their corresponding content types.

Site pages (`pages/*.md`) share `pageBody` in `layout.ts`: a title column with the chapter outline beside the text (a label card with a dotted outline in Field Atlas), then cards linking the other site pages. The 404 page centres its title over a large “404” (an empty mount in Field Atlas) and offers every topic, newest first. GitHub Pages serves `404.html` at any depth, so its links, search results and icons start from the `siteUrl` path; `npm run dev` serves it the same way. Every footer links About, Privacy and Licensing and shows “© years author”, linked to Licensing. The years span the authored topic dates, never the build clock, and there is no “All rights reserved”, because articles and code are openly licensed.

`feed.xml` is a generated RSS 2.0 feed with a summary and complete `content:encoded` article for every topic, newest-added first like the homepage. Titles, descriptions, categories, and creator identity come from existing sources; descriptions are encoded as plain text within RSS's HTML summary field. Feed GUIDs preserve the original explicit index.html permalinks, while link fields use clean canonical URLs; existing subscriptions therefore keep their item identities. Only known creation dates become `pubDate`; known update dates become `atom:updated`, and the channel's `lastBuildDate` is the latest authored date. Day-only dates serialize at midnight UTC as a format convention, never from the build clock. Undated articles remain included without invented dates. Every page has an absolute `rel="alternate"` feed-discovery link; no visible controls are added. The feed is copied into publication output, checked for staleness, and served with RSS MIME type by the local preview. A separate Atom feed is not needed for reader compatibility.

Optional topic dates come from `created` and `updated` in the main README's front matter, as validated `YYYY-MM-DD` strings. `updated` requires `created` and cannot precede it. These dates supply visible labels and article metadata; a redundant same-day updated label is omitted. Without authored dates, the date block and corresponding metadata are omitted. Content dates never consult Git timestamps or the build clock. The visible edition separately identifies the UTC build time and source revision (`YYYY.MM.DD.HHMM+commit`, with `.local` for uncommitted tracked changes). `version.json` carries the exact timestamp and full commit. Set `SOURCE_DATE_EPOCH` and `GITHUB_SHA` for byte-identical reproduction; the regression suite fixes these while checking squash merges and source archives.

The optional `titleBackground` and `titleBackgroundPosition` paths resolve relative to `topics/`. The latter is version 1 positioning JSON, currently `topics/assets/title-wave-position.json`. Its four corners use the main title's font size as one `em`, measured from the title layout box's top-left. The generator converts that geometry to a CSS perspective transform, so both large and miniature versions match exactly without JavaScript or resize handlers. The image is published once as a shared WebP file and reused by all wordmarks through the shared stylesheet. `topics/assets/logo-bg.png` contains transparent teal strokes, with the neutral matte removed so the actual page background shows through in both themes. The original export is retained as `logo-bg-source.png`; `node scripts/prepare-title-wave.ts` regenerates the transparent version without changing its dimensions or saved corner coordinates (requires Playwright Chromium). Dark-mode ink inversion remains in `theme.css`; no opaque backing or stacking-context-dependent blend is needed. The optimized image and positioning JSON are included in the publication bundle; original image sources stay in the repository.

## Reuse

Copy this directory, `scripts/`, `tsconfig.json`, the build dependencies, and a source collection into another repository. Update `topics/topics.json` for collection identity and copy. Customize the shared CSS tokens for the visual style. Topic folders remain independently editable bundles of Markdown, metadata, and assets.

The complete topic authoring guide, including explorer bindings and Markdown excerpt markers, is in [AGENTS.md](../AGENTS.md).

Keep semantic headings, visible focus, native links/buttons, bounded reading widths, reduced-motion support, and keyboard-operable interactions. See [Accessibility](#accessibility) for the specific contracts. Verify desktop and narrow layouts in both themes after changing presentation. Print styles reveal explorer panels and suppress navigation controls.

## Accessibility

Both designs aim at WCAG 2.2 AA; `tests/accessibility.spec.ts` guards the behaviour below.

- **Reader settings** live at the top of the Settings panel, opened by the footer button on every page and device or by “?” while shortcuts are enabled: *Animations* and *Single-key shortcuts*. The footer button and panel are always named “Settings”; the keyboard reference has its own “Keyboard shortcuts” heading, hidden with `.for-keys` on touch screens. When shortcuts are off, the footer’s “?” hint disappears but Settings stays available to restore them. Animations follow the device's reduced-motion setting, and the switch shows that rather than overriding it. Single-key shortcuts (`the-way-i-ai-shortcuts` = `off`) turn off every unmodified key, including “?”, “/” and typing “ai”; ⌘/Ctrl K remains (WCAG 2.1.4). Any new single key must check `data-shortcuts` through `typing()` in `reader.ts`.
- **Overlays:** native `<dialog>` for search, the panel and sharing. The Atlas topic drawer stays a `<details>` without JavaScript; with it, it is `role="dialog" aria-modal="true"` and everything outside it is `inert` while open. Single keys do nothing while any overlay is open (`overlayOpen()`).
- **Announcements** go through `[data-announcer]`, an always-present `role="status"` region; the visible toast is `aria-hidden`. Inside a modal dialog, use a status region in that dialog, since the page behind it is inert.
- **Names:** a control's accessible name contains its visible text (close buttons read “Close (Esc)”). Toggle buttons keep one name and report state with `aria-pressed`.
- **Tab stops:** heading self-links are `tabindex="-1"` (the outline reaches every section); wrapped code blocks are not focusable; scrollable tables are named regions (“Table: <section>”). Dates outside links are focusable and show the exact date on focus.
- **Forced colours** (Windows High Contrast): states shown by a fill use system colours (`Highlight`) in the `forced-colors` block at the end of `theme.css`; the wordmark opts out of the text backplate.
- **Contrast:** text is at least 4.5:1 on every surface, including muted text on code and tint backgrounds. Don't dim text with `opacity`; fade images or backgrounds instead.

## Static delivery and safety

Generated pages and assets exist only in ignored `_site/`; Actions stores preview and deployment artifacts. `npm run build` skips sharing-card rasterization, `npm run build:site` includes it, and `npm run check` validates sources and checks an existing bundle against its recorded edition. Sources are validated before staged output replaces the prior bundle. The preview server serves font, script, stylesheet, Markdown and feed MIME types. Full browser acceptance runs over HTTP with third-party requests blocked where relevant; synthetic artwork bundles retain file-navigation coverage.

The CSP is emitted before content. It denies resources by default, permits local files, and hashes only the pre-paint theme/design script. Inline style attributes remain allowed for the existing interactions; executable inline scripts and handlers do not. Raw HTML in Markdown is limited to comments. URL validation decodes entities before checking schemes. SVG is parsed as XML and restricted to inert SVG elements, with no HTML namespaces, scripting, animation, external resources or entity declarations. The same validator handles SVG images and inline explorers.

`llms.txt` indexes complete topic `index.md` editions; `llms-full.txt` combines them. The Markdown transformer preserves literal code and all listed companion documents. HTML includes alternate Markdown links, and RSS reuses the complete text. `.well-known/security.txt` uses the repository's `/security` page for contact and policy links; private vulnerability reports require GitHub sign-in. GoatCounter and Cloudflare Web Analytics are selected but remain uninstalled; enabling them must update CSP and the privacy page together. Their setup and acceptance steps live in the [operational readiness checklist](../docs/operational-readiness.md).
